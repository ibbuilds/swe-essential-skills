# SWE outcome contract and readiness

The product helps an agent deliver requested software with fewer avoidable
defects, repeated investigations and user interventions. Quality is expressed
through changed behavior, preserved contracts and actual delivery evidence.
Eighteen topic names, a large checklist and green metadata checks are not the goal.

## A selective workflow, not eighteen mandatory phases

Use the [request-to-owner table](project-walkthrough.md#route-to-the-smallest-useful-owner-and-finish-the-request)
to enter at the actual unresolved work. Start from existing intent, contracts,
repository conventions and evidence. Resolve material unowned choices; make
explicitly delegated choices within their bounds. Implement at the responsible
boundary, verify the affected claims and finish the authorized delivery.

| Contract | Completion evidence |
| --- | --- |
| Existing intent is reused | No repeated interview or new whole-project plan for a clear feature or correction |
| Technical changes preserve consumers and data | Relevant failure, compatibility, authorization, lifecycle and recovery behavior is exercised at the real boundary |
| Tests are proportional | Checks can detect the claimed defect; existing adequate evidence is reused and required gates still pass |
| Git work is coherent | Owned staged diff; useful task/recovery checkpoint; authorized push destination and resulting revision confirmed |
| Delivery closes the requested outcome | Artifact/consumer behavior and requested release state are distinguished from local source tests |
| Context stays useful | Existing decisions, sources and results pass between owners without restarting discovery or duplicating artifacts |

The domain owners cover product discovery/definition, requirements/planning,
architecture, construction, backend/client/data, verification/review/debugging,
performance/security, platform/delivery/operations and evolution. Their deeper
references are conditional. Specialized platforms still use applicable official
documentation and actual tools. PM is complementary, never a dependency.

## Closure of the 26 October outcome review

The independent audit read all eighteen entrypoints and relevant references.
Its real isolated CLI task caught a same-day invoice defect through a behavioral
regression, corrected it, retained invalid-input and paid-invoice behavior, fixed
wording, and completed one task commit and one push to a local bare remote.
The unrelated user edit stayed byte-identical and unstaged. A later wording-only
change reused still-applicable code evidence. No substantive defect in that
baseline engineering workflow was demonstrated; that result is preserved rather
than inventing a failure to justify rewriting it.

Construction, planning and verification entrypoints now disclose conditional
detail through their existing local references. Git checkpoints, evidence reuse,
required gates, real target identity and finish criteria remain in the entrypoints.
Planning, architecture and platform guidance make bounded delegation explicit.
This reduces initial instruction footprint; it is not a measured token-saving
or comparative quality claim. A fresh independent executor re-exercised the
updated construction and verification skills on the same bounded task without
seeing the prior findings. Its regression failed before repair and both tests
passed afterward. One coherent task commit and one push reached the local bare
remote; the unrelated notes remained unchanged and unstaged. A separate artifact
grader verified the public CLI's date boundary, paid exclusion, ordering, cents,
invalid-input behavior, owned changed paths and matching local/remote revision.
The source metadata/reference validator also passed. This supports that fixture;
it is not a causal comparison or proof of every engineering domain.

Prior [functional workflows](functional-validation-2026-10-25.md) and
[core engineering cases](core-workflow-checks-2026-10-24.md) remain evidence only
for their stated domains and conditions. Metadata/link validation, artifact
checks, model traces and production behavior are distinct evidence classes.
There is no claim that every domain or model succeeds universally.

## Expert mechanisms retained and adapted

- [Matt Pocock's diagnosis](https://github.com/mattpocock/skills/blob/5beb35b040e3de97e54fa9e386d7e42d15c295c2/skills/engineering/diagnosing-bugs/SKILL.md): a failure-sensitive feedback loop and regression at the causal boundary. We do not require a fixed number of hypotheses or a mandatory test-first sequence for every task.
- [Ras Mic's evidence workflow](https://github.com/michaelshimeles/skills/blob/69558ea1f5328da7b40ba171dfe2171f00ff4884/evidence-driven-testing/SKILL.md): evidence matched to actual runtime behavior, reused when applicable. We use the existing suitable host tools and authorized destinations; a CLI fix does not need video or a public upload.
- [Ras Mic's ownership guidance](https://github.com/michaelshimeles/skills/blob/69558ea1f5328da7b40ba171dfe2171f00ff4884/code-structure/SKILL.md): preserve fitting project conventions and extract only useful shared mechanics. No forced architecture or worktree.
- [Addy Osmani's delivery guidance](https://github.com/addyosmani/agent-skills/blob/aeac41d4d005999432bb7312f7ff06383a91d59d/skills/shipping-and-launch/SKILL.md): observable rollout and recovery. Apply the relevant controls rather than web-specific checks or every test type to all software.
- [OpenAI](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) and [Anthropic](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices): scoped activation, proportional specificity and progressive disclosure.

These are original adaptations of mechanisms, not copied or forked skill text.
The [expert comparison](expert-comparison.md) retains wider source and licensing
context. Ras Mic's refreshed head `11b15767d7587bab11f6c4957507b5f26d1785c7`
changes the README only; the inspected workflow content above is unchanged.
Historical readiness statements remain in Git history and do not freeze current
workflow choices against new human instructions or demonstrated failures.
