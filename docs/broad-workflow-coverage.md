# Broader workflow coverage — 26 October 2026

This pass compares **48 selected mechanisms across 16 pinned repositories** beyond
the earlier Matt Pocock / Ras Mic / Addy Osmani catalog. It reads selected primary
procedures and relevant helpers, compares actual destination instructions, and
retains useful methods without importing every source's framework or mandatory
ceremony. A repository's inclusion is not a claim that every file was audited.
The machine-readable [map](broad-workflow-coverage.json) records exact revisions,
owners, read limits and adaptation boundaries. The earlier
[70-entry catalog](workflow-coverage.md) remains a separate dated inventory;
the counts must not be added into a claim of unique implemented skills.

## What changed

- Requirements: reconcile accepted partial deltas against the current baseline,
  preserving untouched scenarios and concurrent changes and resolving conflicts.
- Construction: prepare documentation alongside code while publishing availability
  claims for the appropriate released, prerelease or draft channel.
- Delivery: one conditional, bounded PR/CI repair procedure joins existing revision,
  failure, feedback, authorization and merge-gate rules. It is consolidation, not
  evidence that the prior suite failed CI tasks.
- Security: calibrated known-defect searches are now locally available to this
  independently portable skill. Debugging already had this mechanism.

PM's existing behavior is preserved: selected capacity, evidence-recovery and
research cases did not demonstrate a failure. Adding mandatory worksheets,
all-source searches or stakeholder rituals would add work without demonstrated
benefit. [Validation](broad-validation-2026-10-26.md) separates executed exercises,
source-aware diagnostics, static coverage and untested specialist depth.

## Selection basis

Official OpenAI and Anthropic authoring guidance favors precise activation,
progressive disclosure, real workflows and observable evaluation. Read this pass:
[OpenAI scoped skills](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra),
[OpenAI Agents SDK workflow experience](https://developers.openai.com/blog/skills-agents-sdk).
The prior pass also read [Anthropic authoring guidance](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices).
Popularity alone is not evidence of correctness: an offline probe of Sentry's
monitor classified a cancelled required check as all-passed. Its useful convergence
method is adapted while retaining this suite's stronger gate and revision rules.

## What this does not bundle

Provider SDK adapters, external trackers, framework CLIs and every language-specific
rule are not installed as hidden dependencies. Their portable mechanisms have
explicit owners; exact provider behavior still requires current official docs.
Secure in-memory erasure remains a specialist task: a source clear does not prove
all copies or optimized builds are erased, and this pass did not validate such a
workflow. The source map retains that boundary instead of counting it as complete.

No global TDD mandate, fixed test ratio, compulsory agent panel, fixed interview
length, automatic outreach, or universal memory/planning directory was imported.
The objective is practical coverage with bounded overhead, not the largest number
of loaded instructions. Coverage is reviewable and dated, not a claim of perfect
activation, universal correctness or measured token savings.
